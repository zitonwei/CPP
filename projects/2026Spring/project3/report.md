# Project 3 实验报告

## 1. 实验题目

基于 C 语言的矩阵乘法实现与优化

## 2. 实验目的

本实验的目标是使用 C 语言实现稠密矩阵乘法，并在保证结果正确的前提下，对基础实现进行一定程度的性能优化。具体目标如下：

1. 实现一个基础版本的矩阵乘法 `matmul_plain()`，作为性能对照组。
2. 实现一个改进版本的矩阵乘法 `matmul_improved()`，提高运行效率。
3. 编写 benchmark 程序，对不同矩阵规模下的运行时间和 GFLOPS 进行测试。
4. 在条件允许时与 OpenBLAS 的 `cblas_sgemm` 进行结果和性能对比。
5. 保证程序结构清晰、接口合理、参数检查完整，并且无内存泄漏。

## 3. 实验环境

- 操作系统：Linux / WSL2
- 编译器：`cc (Ubuntu 13.3.0)`
- 编译选项：`-std=c11 -O3 -Wall -Wextra -pedantic`
- 可选加速：
  - OpenMP：支持，通过 `make USE_OPENMP=1` 启用
  - OpenBLAS：代码已预留接口，通过 `make USE_OPENBLAS=1` 启用

## 5. 数据结构设计

本实验使用如下矩阵结构：

```c
typedef struct {
    size_t rows;
    size_t cols;
    float *data;
} Matrix;
```

该结构具有以下特点：

1. 使用连续内存存储矩阵数据，便于缓存访问和后续优化。
2. 使用 `size_t` 表示维度，便于进行安全的长度和字节数计算。
3. 所有矩阵元素均使用 `float`，满足题目要求。

为保证程序健壮性，矩阵模块实现了以下安全检查：

1. 检查矩阵维度是否为 0。
2. 检查元素个数和字节数计算时是否发生整数溢出。
3. 检查内存分配是否成功。
4. 在矩阵比较和乘法前检查输入矩阵是否合法。

## 6. 基础实现 `matmul_plain()`

`matmul_plain()` 使用最直接的三重循环方式计算矩阵乘法：

```text
for i
    for j
        sum = 0
        for k
            sum += A[i][k] * B[k][j]
        C[i][j] = sum
```

该实现的特点如下：

1. 逻辑清晰，容易验证正确性。
2. 代码结构简单，适合作为基准版本。
3. 时间复杂度为 `O(n^3)`。
4. 对矩阵 `B` 的列访问不连续，缓存局部性较差，因此在较大规模下性能有限。

该函数在计算前会验证：

1. `a`、`b`、`c` 指针是否有效。
2. `a->cols == b->rows` 是否成立。
3. 输出矩阵 `c` 的尺寸是否与结果矩阵一致。

## 7. 优化实现 `matmul_improved()`

为了在保证可读性的前提下提高性能，本实验采用了两种较经典且易于解释的优化策略：

### 7.1 转置矩阵 B

在普通三重循环中，访问 `B[k][j]` 时会沿列方向读取数据，而 C 语言中的二维矩阵按行主序存储，这会导致访存不连续，缓存命中率较低。

因此，本实验先将矩阵 `B` 转置为 `BT`，使原来的列访问变为对 `BT` 的行访问。这样在乘法内层循环中，`A` 和 `BT` 都可以连续读取，从而提升缓存利用率。

### 7.2 分块优化

在完成 `B` 的转置后，进一步采用 blocking / tiling 技术，将矩阵划分为较小的块进行计算。程序中设置了固定块大小：

```c
#define MATMUL_BLOCK_SIZE 64u
```

分块的核心思想是：

1. 每次只处理一个较小的子块。
2. 让当前参与运算的数据尽可能停留在缓存中。
3. 降低大矩阵乘法中的内存访问开销。

### 7.3 可选 OpenMP 并行

若编译时指定 `USE_OPENMP=1`，则启用 OpenMP 并行，将外层块循环并行化，以利用多核 CPU 的计算能力。若系统不支持 OpenMP，默认构建仍然可以正常运行。

### 7.4 优化实现的优缺点

优点：

1. 相比基础实现具有更好的缓存局部性。
2. 保持了较好的代码可读性，便于课堂汇报和答辩。
3. 可以在支持 OpenMP 的环境下进一步加速。

缺点：

1. 需要额外分配一个转置矩阵 `BT`，会增加内存占用。
2. 块大小是经验值，不同平台上未必最优。
3. 没有进一步使用 SIMD 指令，因此仍然存在继续优化空间。

## 8. Benchmark 设计

benchmark 程序包含两部分：正确性测试和性能测试。

### 8.1 正确性测试

在正式 benchmark 前，程序会对小规模矩阵进行随机测试，测试规模包括：

- `4 x 4`
- `7 x 7`
- `16 x 16`
- `31 x 31`

测试内容包括：

1. 比较 `matmul_plain()` 与 `matmul_improved()` 的结果是否一致。
2. 若启用了 OpenBLAS，则进一步比较 `matmul_improved()` 与 `cblas_sgemm` 的结果是否一致。

矩阵比较使用绝对误差和相对误差联合判断，容差设置为：

- `atol = 1e-4`
- `rtol = 1e-3`

若出现误差超限，程序会输出最大绝对误差。

### 8.2 性能测试

根据题目要求，benchmark 的测试规模为：

- `16`
- `128`
- `1024`
- `8192`
- `65536`

对于不同规模，程序采用如下策略：

1. 小规模矩阵重复执行多次，取较优时间，降低偶然误差。
2. 中等规模矩阵减少重复次数，避免测试时间过长。
3. 超大规模矩阵在不现实的情况下直接跳过，并输出明确原因。

### 8.3 安全策略

由于超大矩阵会占用极其巨大的内存，例如：

- `8192 x 8192` 的 4 个矩阵工作集约为 `1 GiB`
- `65536 x 65536` 的 4 个矩阵工作集约为 `64 GiB`

因此 benchmark 中加入了以下保护：

1. 先计算理论内存占用。
2. 若超过安全阈值，则直接跳过，不进行危险分配。
3. 对计算量特别大的情况，也会跳过某些实现，避免程序长时间无响应。

这种做法符合题目中“诚实、可运行、不可伪造结果”的要求。

## 9. 实验结果

以下结果来自当前环境中的一次真实运行，默认未启用 OpenBLAS：

### 9.1 正确性结果

小规模测试结果如下：

- `4 x 4`：`plain` 与 `improved` 一致，PASS
- `7 x 7`：`plain` 与 `improved` 一致，PASS
- `16 x 16`：`plain` 与 `improved` 一致，PASS
- `31 x 31`：`plain` 与 `improved` 一致，PASS

说明优化版本在当前测试范围内与基础版本保持一致，结果正确。

### 9.2 性能结果

| 矩阵规模 | 实现方式 | 时间（秒） | GFLOPS | 说明 |
|---|---|---:|---:|---|
| 16 x 16 | plain | 0.000001 | 6.548 | PASS |
| 16 x 16 | improved | 0.000001 | 8.706 | PASS |
| 128 x 128 | plain | 0.000835 | 5.020 | PASS |
| 128 x 128 | improved | 0.000452 | 9.272 | PASS |
| 1024 x 1024 | plain | 跳过 | - | 基础版本计算量过大，未实际执行 |
| 1024 x 1024 | improved | 0.233352 | 9.203 | PASS |
| 8192 x 8192 | plain / improved | 跳过 | - | 工作集约 1 GiB，超过安全阈值 |
| 65536 x 65536 | plain / improved | 跳过 | - | 工作集约约 64 GiB，超过安全阈值 |

### 9.3 结果分析

从结果可以看出：

1. 在 `16 x 16` 和 `128 x 128` 的规模上，优化版本均快于基础版本。
2. 在 `128 x 128` 时，优化版本 GFLOPS 接近基础版本的 2 倍，说明转置与分块已经带来了明显的缓存收益。
3. 在 `1024 x 1024` 规模下，基础实现由于时间复杂度高且访存模式较差，不再适合继续作为实际 benchmark 对象，因此程序选择跳过。
4. `8192 x 8192` 和 `65536 x 65536` 在普通实验环境下内存需求过高，如果强行运行，风险较大，因此程序进行了安全跳过。


## 11. 程序健壮性分析

本实验在实现中重点考虑了以下健壮性问题：

1. 对所有输入矩阵进行合法性检查。
2. 对矩阵维度和输出尺寸进行匹配检查。
3. 对矩阵元素总数和字节数进行溢出检查。
4. 对内存分配失败进行处理，避免程序崩溃。
5. 对超大 benchmark 场景进行安全跳过。
6. 所有动态分配的内存在使用结束后释放，未发现内存泄漏。

## 12. 本实验的不足

虽然本实验已经实现了基础优化，但仍有一些不足：

1. 没有实现 SIMD 向量化，峰值性能仍然有限。
2. 分块大小固定为 64，没有根据不同 CPU 自动调参。
3. 当前 benchmark 主要关注方阵情况，没有测试更一般的矩形矩阵乘法。
4. OpenBLAS 对比功能已实现，但当前环境中没有实际测得对应数据。

## 13. 改进方向

后续可以从以下方面继续改进：

1. 引入 SIMD 指令，例如 AVX2 或 AVX-512，对内层循环进行向量化。
2. 采用更复杂的矩阵打包技术，进一步提高缓存命中率。
3. 根据不同平台自动调整 block size。
4. 增加多组 benchmark 结果统计，例如平均值、最优值和标准差。
5. 测试不同线程数下 OpenMP 的加速效果。
6. 在具备 OpenBLAS 环境时补充与工业级库的性能对比结果。

## 14. 实验结论

本实验完成了一个结构清晰、可编译、可测试的 C 语言矩阵乘法项目，实现了基础版本和优化版本两套算法。

实验结果表明：

1. 优化版本在保证正确性的前提下，较基础版本具有更好的运行性能。
2. 转置矩阵 `B` 和分块优化能够有效改善访存局部性，是一种简单但有效的优化策略。
3. 对于极大规模矩阵，工程上必须考虑内存和运行时间限制，合理跳过不现实的测试同样是健壮程序设计的一部分。

总体而言，本实验达到了课程项目对于正确性、清晰性、鲁棒性和适度优化的要求。
